# パーソナルトレーナー向けプロダクト ナレッジベース

パーソナルトレーナー向けの「コンサル・スクール／AIツール」プロダクトローンチに向けて、
情報を継続的に蓄積していくためのフォルダ。チャットボット構築・教材化・コンサル内容構築に使う想定。

このリポジトリ（task-manager）とは無関係だが、セッション上このブランチが使える場所のため、
ナレッジ蓄積の置き場として利用している。

## このフォルダの中身

| ファイル | 内容 |
|---|---|
| `roadmap-and-logging.md` | 「今は人によるコンサル→将来AI/コンテンツへ移行し労力を減らす」というロードマップと、コンサル後に記録すべきケースログのテンプレート |
| `curriculum-summary.md` | 人間向け研修カリキュラムとして整理したサマリー版（集客→商品→セールス→継続→数字管理→仕組み化） |
| `A-business-knowledge.md` | 経営・集客・セールス・事業構築ナレッジ 全50項目（Lv2完全版）。トレーナー自身の経営をAIが診断・コーチングするための知識ベース |
| `B-client-knowledge.md` | クライアント向けトレーニング・食事・習慣化ナレッジ 全50項目（Lv2完全版）。トレーナーの「顧客」をAIが指導・診断するための知識ベース |

A・Bともに「定義／目的／良い例・悪い例／AIが聞く質問／AI診断／達成基準」という統一フォーマットで、
最終的に「答えを与えるAI」ではなく「本人が自分で考え、自立できるようにするAI」という一貫した思想で設計されている。

## プロダクト概要（把握できている範囲）

- 想定ユーザー：パーソナルトレーナー（開業・独立系）
- 提供したい価値：経営・集客・セールスの型と、クライアント指導の型の両方を体系的に指導
- 想定アウトプット形態（本人の発言より）：チャットボット、教材、コンサルの内容構築の3つに将来的に使う予定（開業時にチャットボット化も視野）
- A（経営ナレッジ）＝トレーナー自身の経営を診断・指導するための頭脳
- B（クライアント知識）＝トレーナーの生徒への指導を診断・設計するための頭脳

**【確定】提供形態：人（あなた）によるコンサル・スクール。トレーナーはAIを直接触らない。**
A・Bのナレッジは、あなたがコンサル・指導する際に使う「診断ロジック・台本・思考のフレームワーク」（裏側の武器）であり、
チャットボットとして表に出すのは将来的な展開の一つであって、現時点の主商品ではない。
→ そのためLPは「AIが診断します」ではなく、**「体系化されたメソッドを持つ人（あなた）が教える」**という、
　提供者の権威性・メソッドの独自性を軸にした構成にする。

## LP制作に向けて、まだ埋まっていない情報

過去の会話で指摘した、LP（ランディングページ）を作る上で必須だが未取得の項目：

1. **ターゲット像**：どんな悩みを持つトレーナー向けか（例：フリーランス1年目、単価が上がらない等）
2. **Before→After**：導入後にどう変わるか（例：月商30万→100万等の変化）
3. **差別化・独自性**：他のトレーナー向けコンサル／ツールと何が違うか
4. **実績・証拠**：本人の実績、既存クライアントの成果・声
5. **提供形態・価格・期間**：商品自体の値段・期間・提供方法（オンライン/対面、月額/買い切り等）
6. **講師・提供者の権威性**：プロフィール・経歴
7. **申込のハードルを下げる要素**：保証、FAQ、限定性など
8. **CTA（LPのゴール）**：無料カウンセリング申込／LINE登録／資料請求／説明会申込のどれか

→ 上記が揃った時点でLPコピー・構成の作成に着手する（LPは「作らないでほしい」という初期指示があった経緯があり、
　本格的なLP制作に入る際は改めてユーザーに形式（Webページとして実装するか、コピー文章のみ用意するか）を確認すること）。

## 今後の運用方針

- ユーザーから新しい資料・ナレッジが送られてきたら、このフォルダに整理して追加していく
- 内容を変更・追記した場合は、git commit + push でこのブランチに保存する
- 新しいセッションでもこのリポジトリ（このブランチ）を開けば、ここまでの蓄積を参照できる
