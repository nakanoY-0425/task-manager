## 01. 商品設計フレームワーク（記入用テンプレート・現時点は未記入）

以下は商品設計を詰めるための質問項目。`▼記入欄▼`列はまだ空欄。今後ここが埋まったら、このファイルにも反映する。


**商品設計**

- **商品コンセプト** — どんな理想の未来・悩みを持つ人が、どんな商品を手にして、どんな成果を得るのか
- **ローンチ企画の仮タイトル** — 商品コンセプトを「企画」として打ち出す核のメッセージ
- **間違った常識（仮想敵）** — ターゲットが信じている、成果が出ない原因の常識。これを壊すのが最強のフック
- **企画が約束する最大のベネフィット** — 参加するだけで即座に得られる価値
- **なぜ「あなた」から学ぶべきか** — 実績・権威性に加えて、思想・在り方・失敗談を言語化する
- **なぜ「今」参加すべきか** — 限定性・緊急性（期間限定／先着／今だからこそ）
- **コンセプトの抽象度チェック** — 具体的すぎると母数が減る。おさる式は「抽象的」に振ってパイを広げる

**ターゲット**

- **年代** — 商品のターゲットと発信ブランディングのターゲット
- **性別** — 女性メイン／男性のみ／男女両方
- **地域** — 特定の商圏がある商品のみ記入
- **年収** — 属性の割合が多い仕事から平均年収を割り出す
- **職業** — 主婦・パート／サラリーマン・学生 など
- **悩み** — 顕在的に認識している悩み
- **共感できる要素** — その悩みに共感を生むエピソード・商品開発秘話
- **認識している問題・課題** — 理想ではない状態／理想を叶えるための課題
- **使う言葉** — 普段使う言葉・単語。LINEやLPで同じ言葉を使わないと刺さらない
- **接点のあるコミュニティ** — 価値観を共有している場（家族・大手プロダクト・サロン・SNS）
- **認識している解決策** — 自分で認識している解決策を列挙し、そのデメリットを突く
- **理想の状態（目先）** — すぐに叶えたいこと ※メリット寄り
- **理想の状態（遠い未来）** — 最終的に叶えたいこと ※ベネフィット寄り
- **避けたい未来（目先）** — すぐに改善したい問題
- **避けたい未来（最悪）** — そのままで居続けた場合の最悪の結末

**商品理解**

- **ハウスリストの教育状況** — これまでの価値提供／理解度／信頼残高
- **権威性** — なぜあなたが提供する必要があるか。信頼につながる実績
- **限定性** — 希少性・販売期限・数量制限・特定条件下での案内
- **価格** — 商品価格・割引の有無
- **特徴、長所** — 品質・機能性・利便性・デザイン／価格に対するコスパ
- **解決できる課題** — 理想の未来へ行くための障壁のうち、商品で解決できるもの
- **お客様の声** — ビフォーアフター。どんな成果が得られるか
- **課題の解決策** — 商品の手法で具体的にどう解決するか

**提供方法**

- **サポート** — 方法／回数と時間／保証（延長・返金）
- **コンテンツ内容** — カリキュラム構成と提供コンテンツ一覧

**ローンチ設計**

- **ローンチ本番日（D-Day）** — セミナー開催日・個別相談開始日。ここから全部を逆算する
- **告知日（P-Day）** — 本番日の7〜14日前が目安
- **メイン特典** — リスト登録と引き換えに渡す最も強力な特典（＝セミナー参加権 等）
- **集客LPの4部構成** — Why（なぜチャンスか）／What（何を得るか）／How（どうやるか）／Action（どう動くか）
- **プリローンチ動画 第1話（Why）** — 間違った常識を壊し、新しいチャンスに気づかせる
- **プリローンチ動画 第2話（What）** — 全体像（ロードマップ）を提示し、実績者の声で再現性を証明
- **プリローンチ動画 第3話（How）** — ノウハウの一部を具体的に解説し、成功の疑似体験を渡す
- **プリローンチ動画 第4話（Action）** — 本商品・個別相談を唯一の手段として提示し、限定性で締める
